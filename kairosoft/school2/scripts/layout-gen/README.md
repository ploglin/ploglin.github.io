## 檔案

| 檔案 | 角色 |
|---|---|
| `towns.js` | **城鎮設定表**(尺寸／preset 變數名／SVG 檔名／`page` 子頁目錄／`pond.maxCarve` 水塘破壞預算／棋盤路網參數／`spine` 幹道脊椎／`flow` **動線環化開關**)。唯一的「哪個城鎮」開關。 |
| `engine.js` | 從 sim 抽 items/SPOTS/該鎮地形,複製判定邏輯(4×4 景點、斜坡推導、可達性 BFS、包圍判定、**動線指標 `flowMetrics`**、分享碼 encode/decode)。 |
| `stages.js` | **解鎖階段對照表**:item id → 遊戲四階段(1 農村／2 發展／3 有望／4 名門),來源標 `DEV_GUIDE` 或 `推定`。輸出 `itemStage()`／`itemCond()`／`spotStage()`／`spotKeyItem()`。 |
| `design2.js` | 路網佈局器:鋪路 → 切 4×4 街廓 → 街廓填景點骨架(唯一設施不重複、整組放置有包圍守衛、**街廓階段偏好**)。 |
| `builder.js` | **城鎮無關的共用機具**:4×4 補位、分區填充、綠化、加開校門、**鑿水道**、打通高地坡道、**破壞地形補環 `breakTerrain()`**、高地開發、斷頭路整理、**材質重鋪 pass**、**環化 pass**(動線)、驗證輸出。 |
| `final.js` | 健康鎮的**設定檔**(分區優先;15 個分區、段式 `spine`、8 間教室＋行政六件套 `PREPLACE`、兩塊高地園區＋高地運動台)。 |
| `east.js` | 冬郵小鎮的**設定檔**(分區優先;16 個分區、湖心島登島坡道)。 |
| `hill.js` | 百靈山丘的**設定檔**(2026-08 分區優先重寫：27 個分區、**29 組景點全部手放**、田埂路覆蓋、南門、孤立口袋景觀化)。 |
| `valley.js` | 溪谷小鎮的**設定檔**(**分區優先,2026-08 重做**:開局 `ERASE` 6 格、臺地肩／西高地／星空台／開羅廣場的 `PREPLACE`,**9 教室 2 辦公室全部釘在台地上**、坡道保留帶＋新坡道斷言、南門在 `prepare()` 裡加)。 |
| `lake.js` | 湖岸小鎮的**設定檔**(24×24;鎖喉走廊保護格、清一格 e2 樹墩「長出」踏石橋、被湖圈死的鱷魚池拆遷、**運動園區整組手放在北高地**＋自鋪水泥步道骨架、`HAND_PLACED` 把手放好的景點排出 `spotOrder`、走不到的草地口袋景觀化)。 |
| `verify.js` | **可重跑的驗證器**,只吃分享碼(含動線指標 INFO 與 `flow.check` 開的孤立格 PASS)。 |
| `gen-assets.js` | 由分享碼產生 `layouts/*.svg`(含鋪面圖例)與頁面要用的表格 HTML(景點座標／設施統計／**階段 × 分區**)。 |

`code.txt` / `code-east.txt`、`zones-*.json`、`*-table-*.html` 都是產物,不是輸入。
(`zones-*.json` 由 `final.js`／`east.js` 寫出,是 `gen-assets.js` 產「階段 × 分區」表的唯一分區來源
——`gen-assets` 只吃分享碼,本來看不到設定檔裡的 ZONES。)

```sh
node final.js                 # 健康鎮 → code.txt + zones-health.json
node east.js                  # 冬郵小鎮 → code-east.txt + zones-east.json
node gen-assets.js            # code.txt      → layouts/health-perfect.svg + spots/fac/stage-table-health.html
node gen-assets.js east       # code-east.txt → layouts/east-perfect.svg  + spots/fac/stage-table-east.html
node verify.js health         # 驗 code.txt 本身
node verify.js health page    # 驗「layouts/health/index.html 上實際貼的那一串分享碼」
node hill.js                  # 百靈山丘 → code-hill.txt + zones-hill.json
node gen-assets.js hill       # code-hill.txt → layouts/hill-perfect.svg  + spots/fac/stage-table-hill.html
node verify.js east page
node verify.js hill page
node valley.js                # 溪谷小鎮 → code-valley.txt + zones-valley.json
node gen-assets.js valley     # code-valley.txt → layouts/valley-perfect.svg + spots/fac/stage-table-valley.html
node verify.js valley page
node lake.js                  # 湖岸小鎮 → code-lake.txt + zones-lake.json
node gen-assets.js lake       # code-lake.txt → layouts/lake-perfect.svg   + spots/fac/stage-table-lake.html
node verify.js lake page
node stages.js                # 自檢:列出 items 註冊表裡還沒登記解鎖階段的 id ＋ 各景點的階段
```

## 佈局頁的結構

```
layouts/index.html          完美佈局 hub:城鎮卡片 + **共用的設計原則(只寫一次)** + 入門小範例
layouts/<town.page>/        各鎮子頁:地圖 / 分享碼 / 統計 / 景點座標表 / 設施表 / 施工順序
layouts/*-perfect.svg       兩鎮共用同一層的 SVG(子頁以 ../xxx-perfect.svg 引用)
```

各鎮子頁頁首有一排**城鎮切換 pills**(連到兄弟頁,現在所在鎮標 `.on`),
擴充到五鎮時只要在 pills 清單加一筆。子頁是**巢狀 slug**(`layouts/<鎮>/`),
`scripts/gen-game-nav.js` 只掃遊戲根目錄的第一層,所以**不會**進遊戲功能列
(也不必登記 LABELS、不會出現未知 slug 警告);橫向切換由 pills 與 hub 負責,
麵包屑則是「口袋學院物語2 → 佈局範例集 → ○○鎮完美佈局」。
`scripts/gen-related.js` 的 `RELATED` 已登記 `layouts/health` / `layouts/east`
(巢狀 key,href 要多退一層)。新增城鎮頁後重跑 `node scripts/gen-related.js`
與 `node scripts/gen-sitemap.js`。

把 `code-*.txt` 貼進該鎮子頁的「在模擬器開啟」按鈕、表格 HTML 貼進對應
`<tbody>`,然後**一定要跑 `node verify.js <town> page`**——它直接從該鎮子頁
抓分享碼解碼重驗,確保頁面上的圖就是驗過的那張。全部 PASS 才算完成。

## 加一個新城鎮

1. `sim/index.html` 要有該鎮的 `PRESET_XXX_DATA`(並鏡射到 `sim/presets/`)。
2. `towns.js` 加一筆:`rows`/`cols`(= 座標上限 − 1)、`preset` 變數名、`svg` 檔名、
   `page`(子頁目錄名)、`pond.maxCarve`(允許破壞幾格水塘)、
   `roads`(橫向大道列、縱向街道欄、街廓帶——街廓寬高盡量對齊 4,因為 4×4 就是景點窗口)、
   `spine`(幹道脊椎:把兩座校門串起來的 1 橫 1–2 縱,材質重鋪 pass 會鋪成道路)、
   `flow`(動線環化開關;**重排完、確認孤立通行格已經是 0 才開 `check: true`**)。
3. 抄 `east.js` 當範本,只改分區設定(每區都要有 `stage` 與 `mat`);**不要複製 engine/builder**。
4. `verify.js` / `gen-assets.js` 的 `CODE_FILE` 對照表加一行。
5. 新增 `layouts/<page>/index.html`(抄現有子頁,head 靜態手寫 SEO)、
   把該鎮加進 hub 的城鎮卡片與所有子頁的 pills 清單,
   再跑 `node scripts/gen-related.js` 與 `node scripts/gen-sitemap.js`。

> ⚠️ 進入點腳本**必須**在 `require('./engine.js')` 之前先 `require('./towns.js').select(key)`——
> engine 與 design2 會在載入當下把 `gridRows`/`gridCols` 解構成常數。

## 產生器的固定假設(頁面上也要照這樣說明)

- **水塘可以破壞,但要有預算**:實機確認**水塘可被建設覆蓋、破壞成平地**(保留原高度)。
  `towns.js` 的 `pond.maxCarve` 是該鎮允許破壞的格數**總上限**,`verify.js` 檢查
  「破壞數 ≤ 上限」「沒有無中生有的新水塘」「鑿開的格子保持原高度」,並列出破壞座標。
  破壞分兩筆帳,設定檔要分開給預算:`pond.channel` 給 `carveWaterChannel()`(接進走不到的陸地)、
  差額給 `breakTerrain()`(補動線環)。目前:健康鎮 0 格、
  **冬郵小鎮 2 格**(湖心島登島坡道,`east.js` 的 `prepare()` 手動擦成空地→斜坡;
  `carveWaterChannel` 在坡道做完後已無收益、實際鑿 0 格,`breakTerrain` 已不使用)、
  百靈山丘 0 格(水面全記在 e3,鑿了也只剩孤格)、
  溪谷小鎮 0 格、**湖岸小鎮 0 格**(146 格湖面全保留 —— 山中湖記在 e3、東北角湖只圈住 2 格空地,
  鑿了都沒有收益;真正要打通的南北動線改用「清一格 e2 樹墩長出斜坡」解決,見下)。
- **原始斜坡一格不動**:斜坡是高低差推導出來的,蓋東西上去高地就上不去了。
  反過來,**新增斜坡是合法手段**:把高地上的植栽／草地「擦成空地」遊戲就會自動判成斜坡
  (`openPlateaus()` 打通高地、`breakTerrain()` 開捷徑都靠這招)。任何情況下
  **elevation 一格都不准動**——`breakTerrain()` 跑完會斷言 elevation 簽章與原始斜坡集合。
- **既有校舍原則上保留**;只有卡在幹道上的小農舍(小雞／小農場／田地／百葉箱)
  與「怎麼蓋都走不到」的建築會拆遷,並在別區重建。`verify.js` 會把拆掉的清單印出來
  (**逐棟比對**,同型別相鄰不會互相遮蔽)。
  ★ 「卡在幹道上」**先當成可以救**:`prepare()` 跑在 `layRoads` 之後,把那幾格寫回
  原本的型別就等於「這幾格不鋪路」。健康鎮 3 棟原生農舍就是這樣全部救回來的
  (拆除 3 → 0 棟、棟數 163 → 165),代價只是那兩條路被截斷、死路支線 15% → 20%。
  **拆除數是要誠實揭露的項目,死路占比沒有門檻 —— 兩者衝突時保留建築。**
- **高地可以蓋房**,每列最外側留步道接坡道;步道材質由 `fillPlateau` 的 `walkMat` 決定
  (公園類高地＝草地小徑、設施類園區＝走廊)。
  `fillPlateau` 是**逐格放置**,多格設施會被 `sizeOf` 判掉並跳過 → **`zone.fac` 只能列 1×1**。
  設施改尺寸(例:游泳池／體育館 1×1 → 2×2)時要回頭清掉高地清單裡的那一項,
  不然它每輪白佔一個位置、那格只會被綠化掉(健康鎮東高地曾因此從 16 棟掉到 12 棟)。
- **不放 `hidden` 磚**(例如 `slope`),地圖上不能有玩家蓋不出來的東西。

## ★ 可達性:兩個修掉的真 bug(最容易再犯的一組)

### ㈡ 每一棟各自要有門(2026-08)

`blockedBuildings()` 原本把**同型別相鄰的格子 flood fill 成「一棟」**,
於是兩間並排的 2×2 教室只要其中一間有門就一起過關,另一間其實進不去。
改成**先按 w×h 切回一棟一棟**(與 verify 的 footprint 檢查同一把尺)再逐棟判定。
照出:冬郵 1 棟、健康 1 棟、湖岸 3 棟(溪谷／百靈 PASS)。

冬郵那一棟是**東緣兩間並排的原生養豬小屋**:北邊 `X13/Y2` 北西是水塘(e2)、
東是**地圖邊界**、南是另一間豬舍 → 四面都不是出入口。開門只剩「再鑿一格水塘」,
但預算已全數用在登島坡道(2/2)。處理:**拆南邊那間、那格改鋪草地當參道**
(`X15/Y2 草坡 → X14/Y2 草地 → X13/Y2 豬舍`,同高度)。
比拆北邊那間好 —— 留下的是原地保留的原生建築＋一條真走道,實測也較好
(143 棟 vs 141、死路支線 21% vs 22%)。

> **⚠ `verify.js` 的「拆除的既有建築」對同型別不敏感**:只要地圖上還有別的養豬小屋,
> 它就不會報告這一棟被拆了。**拆遷要靠人記錄在頁面上,不能等驗證器提醒。**

### ㈠ 出入口的三個條件(2026-07)

「這棟建築有出入口嗎」必須同時滿足**三個**條件,少一個就會產出
**驗證通過、實機永遠走不到**的建築:

1. 鄰格 **可通行**(`PASSABLE`)
2. 鄰格 **從某座校門走得到**(`computeReachability`)
3. **從那格真的踏得進這一格**(`canStep` —— 吃高低差,只有斜坡能跨階)

第 3 條原本在**四個地方**同時漏掉,所以「排得下」與「走得到」用了兩把不同的尺,
產生器會很樂意把房子蓋在它自己認為合法、實際卻進不去的位置:

| 位置 | 角色 |
|---|---|
| `engine.blockedBuildings()` | 驗證「0 棟被包圍」 |
| `design2.parcels()` 的 `served` | 決定哪些格是「可蓋建築的 slot」 |
| `builder.fill()` 的 `servedAt()` | 分區填充的放置條件 |
| `builder.fallback()` 的 `served` | 4×4 補位的放置條件 |

**四處現在都補上 `canStep`。** 冬郵補上後立刻現出 2 棟真的走不到的建築
(原生百葉箱 `X6/Y3`、島上第 4 隻動物 `X27/Y7`),溪谷 7 棟、百靈 3 棟
(那兩鎮的「崖下借位」設計本來就踩在這個漏洞上)。
**溪谷那 7 棟已在 2026-08 的分區優先重做裡正面解決**:3 棟原生建築靠**兩格橡皮擦**
長出坡道(見「溪谷小鎮的七個特殊處理」),另 4 棟是舊圖把新建築排在崖邊造成的 ——
四處的尺改成同一把之後,產生器根本不會再排到那種位置,**不必手動挪位**。
**百靈那 3 棟也在 2026-08 的分區優先重做裡正面解決**：整條崖下行政帶的門面改成崖下同高的 c19／c24 縱街與 AV r15，跨崖窗口照樣成立、但不再拿高台走廊當出入口（見「百靈山丘」一節）。

**修對之後很多事會自己好**:`openPlateaus()` 的階段 2 本來就會「救援被包圍的既有建築」,
只是以前判定錯誤、看不見百葉箱;把尺改對,它自動擦掉 `X5/Y4`、`X6/Y4` 兩格田埂路
長出兩格斜坡,參道就通了(全圖斜坡 27 → 29)。同理,`parcels()`/`fill()` 修對之後
就不會再把建築放進湖心島南端那格死口袋 —— **不必手動列豁免或手動挪位。**

> 教訓:**判定邏輯的漏洞會偽裝成「設計得很好」**。舊圖的「0 棟被包圍」不是設計成果,
> 是量錯了。修判定比修個案重要 —— 冬郵這次一行手動修正都沒寫,兩棟都是判定改對後
> 自動解決的,而且動線指標反而變好(死路支線 20% → 17%、端點 21 → 18);最終加上養豬小屋拆遷落在 143 棟、21%。

## 分區優先(zone-first):分區是第一公民,鋪面是分區的表達

> **2026-07 大改。** 舊架構的目標是「湊滿 29 景點」,鋪面是事後補上的視覺語意,
> 於是產出「農牧園區裡站著校長室與操場」、一條街材質東一塊草地西一塊道路的圖。
> 新原則(使用者指定):**先劃出語意清楚、成塊的分區,再用對應材質的通路連起來;
> 景點數降級為「良好分區前提下的最大可成立數」,不硬湊。**

|---|---|---|---|
| 走廊 `wood_path` | 校舍內廊道 | 教學／行政／生活／舊校舍**分區內部** | 舊版是全圖預設值;新版**只出現在校舍分區內** |

| 水泥地 `concrete` | 戶外運動硬鋪面 | 運動園區的通路與場地周邊 | 舊版**只當 1–2 格門前廣場、不當通道**;新版是運動區的**正式通路材質** |

### `builder.paveMaterials(g, { zones, spine, keep })`

在 `report()` 之前跑,只改「已經是通行鋪面且 elevation === 1」的格子。

**先切街道段,整段一起鋪**——這是新架構的關鍵。逐格投票會讓同一條路變成
「草草廊廊草草草」,正是使用者說的「東一塊草地西一塊道路的亂拼」。所以:

1. **街道段** ＝ 同一條 AV 列／ST 欄在兩個路口之間的那一截(恰好等於 `ROW_BANDS`／
   `COL_BANDS` 的一個區間)。整段票數加總後**整段鋪同一種材質**。
2. **路口**留到最後,取四鄰已鋪好的街道段的多數決(路口屬於在那裡交會的那幾條街)。
3. 其餘鋪面格(原生道路、環化補的格、街廓內部路面)逐格解析。

每一格的材質由三條規則決定(`matResolver`,與 `loopify` 共用一份):

1. **幹道規則**:落在 `spine` → **道路**。幹道穿過任何分區都還是道路。
2. **區內規則**:格子落在某街廓內部 → 直接取該街廓的 `mat`。
3. **臨街面規則**(核心):一條街的材質由「**誰的門開在這條街上**」決定 ——
   四鄰每有一棟建築(校門也算)就投 3 票給**它所屬街廓**的 mat;街廓幾何相鄰再補票
   (正交 2、斜角 1,決定沒有建築臨街的穿越型街道);票數最高者勝,平手才用
   `MAT_PRECEDENCE = ['asphalt','concrete','grass','wood_path']`(越對外／越硬越往界面走)。

   → 門口全是教室的街自動變走廊、體育館旁變水泥地、豬舍旁變草地、校門旁變道路。

**明列例外**:`keep`(鑿出來的跨水木棧橋)一律走廊 —— 全圖唯一刻意脫離分區材質的地方
(四種鋪面裡只有木造廊下讀得出「棧道」,而它跨的是水面、不屬任何陸上分區)。
高地步道(elevation > 1)不吃街廓規則,由 `fillPlateau` 的 `walkMat` 決定。

**已汰除(刪掉,不是留著不用)**:
- ✗ 舊「兩側 mat 優先序 **道路 > 走廊**」—— 只認兩種材質,水泥地與草地永遠選不到。
- ✗ 舊「**水泥門前廣場 pass**」—— 體育館／泳池／道場旁硬塞 1–2 格 `concrete`。
  水泥地升格成運動區正式通路後這就是多餘補丁;連 `loopify` 的「門前廣場一格不動」
  豁免與 `PLAZA_HOST` 常數一起移除。
  **⚠ 副作用:其餘四鎮重新產生時水泥地會變 0**(它們的 ZONES 只宣告道路／走廊),
  這正是它們要跟進的工作 —— 各鎮需要宣告一個 `mat: 'concrete'` 的運動分區。

這個 pass **必須是景點中立的**:跑完會用 `activeSpots` / `blockedBuildings` 斷言
(景點一個都不能少、被包圍建築不能變多),不中立就直接 throw。
另外會印「材質 fallback N 格」——那是四周沒有任何街廓宣告 `mat` 的格子,
分區優先架構下不該有無主的街道,看到就去設定檔補分區。

### 分區語意約束:`engine.itemKind()` / `zoneMismatch()`

**鋪面本身就是分區語意**,不必多一個欄位 —— `ZONES[].mat` 直接推出該區收什麼設施:

| mat | 分區語意 | 收什麼 |
|---|---|---|
| `wood_path` | `indoor` | 教室／專科／辦公／室內生活機能 |
| `concrete` | `sports` | 戶外運動設施(含更衣室) |
| `grass` | `farm` | 動植物農牧、公園自然面 |
| `asphalt` | `open` | 玄關:**只收中性設施**(紀念物／長椅／公告欄／販賣機／校門…) |

`itemKind()` 以 items 分類為底再手動修正:校門→`open`、更衣室→`sports`、
紀念物／長椅／公告欄／販賣機／洗手間／飲水處／水井／茶室／焚化爐等**戶外小物**→`open`
(這些放哪都合理,不該被罰)。

**`design2.build()` 的排序鍵改成字典序「分區完整性 → 要動的格數 → 階段偏好」**。
舊版主鍵是「格數最少」,於是景點骨架完全無視分區。`zonePenalty` ＝這一組計畫裡
「蓋錯區」的棟數;`builder.fallback()`(4×4 補位)套同一把尺排序。兩者都會印
`！分區語意妥協：<景點> 有 N 棟蓋進語意不合的分區`,**照實記錄、頁面要交代**。

**幾何上的硬限制(改不掉,只能誠實揭露)**:4×4 景點窗口不看分區邊界,而一個景點的
三件材料常常跨語意(「動作」＝道場＋社團教室＋彈跳床是運動的,「吃醋」＝焚化爐＋餐廳＋
家政室是室內的),窗口只有 16 格、想同框就得擠進同一個街廓。冬郵最後 143 棟裡有
**17 棟蓋錯區**(另 3 棟是「既有校舍一棟不拆」造成的)。**要壓更低就得放棄景點。**

### 右尺寸化:一個 4×4 街廓只放得下 4 座 2×2

設施尺寸大修正後(操場／棒球場／足球場／道場／電腦室／理科室／音樂室／美術室／
家政室／多功能室全是 2×2,天象館橫 2 格),`ZONES[].fac` 必須按這個現實配額:
**16 格 = 4 座 2×2(要對齊四象限)或 16 座 1×1**。舊設定檔常見一個街廓列 7 項
(多半 2×2 ＝ 需要 28 格),於是每輪印一堆「無處可放」、位置被白佔。
冬郵舊設定檔在尺寸修正後只剩 **111 棟**(舊頁面寫 124),右尺寸化後回到 **143 棟**。

### 段式 `spine`

`spine.av` / `spine.st` 的每一筆可以是整條線(`14`)或**一段**(`[14, 9, 19]` ＝ r14 的 c9–c19)。
段式讓「對外幹道」名實相符:冬郵整條 r14／c9／c19 會有 **57 格道路橫貫全圖**,

## 動線流暢優先於景點配置:環化 pass

**新的設計優先序**:29/29 景點與 0 棟被包圍仍是硬指標,但兩者達成之後還要顧
**路網本身好不好走**;實務上兩者大概率不衝突,只有真二選一時才讓景點。
舊管線只驗「每棟走得到」,於是留下兩類沒有動線價值的格子:

1. **走不到的假路面** —— 街廓綠化把剩餘空地鋪成 `grass`,而草地是**可通行**的,
   四面被建築圍住的那格就變成誰也走不進去的假草皮;更隱性的是「度數都 ≥ 2、
   整塊卻接不到校門」的 2×2 中庭(看起來是條路)。
2. **死路支線** —— 從度 1 端點走到第一個岔路口的那一段,走進去只能原路折返。

### 指標定義(`engine.flowMetrics(g)`,verify 與 builder 共用一份)

| 名稱 | 定義 |
|---|---|
| 度數 | 四鄰中 `canStep` 走得過去的**通行格**數。**校門算一度**(gate 不在 `PASSABLE`,但它就是進出口,不然門前那格會被誤判成死路) |
| 孤立通行格 | 度 0 的通行格。**視同缺陷** |
| 走不到的通行格 | 從任一校門 BFS 到不了的通行格(孤立格是其特例) |
| 死路端點 | 度 1 的通行格 |
| 死路支線 | 每個端點沿唯一路徑走到第一個度 ≥ 3 節點,路上的格(多端點共用只算一次) |
| 占比 | 死路支線格 / 通行格 |

`verify.js` 每張圖都印這幾個數字當 **INFO**;**「孤立通行格 = 0」是 PASS 檢查**,
由 `towns.js` 的 `flow.check` 開關控制 —— 只有已重排的鎮才開,**五鎮現在全部開了**。
**死路占比刻意不設門檻**:五鎮地形差太多
(百靈山丘環化後 7%、湖岸分區優先重排後 11%,是湖面與斷崖決定的),一刀切只會逼出爛決策。

### `builder.loopify(g, opts)`

跑在 `paveMaterials` **之後**、`report` 之前。三個階段依缺陷嚴重度排,
**整組重跑到收斂**(`sweeps`,預設 3):

1. **孤立通行格** —— 先試「接回路網」(只認接完**度 ≥ 2** 的,不然只是把死路挪一格),
   不行才改種綠化。
2. **假動線口袋**(走不到但度 ≥ 2) —— 先試鋪一格裝飾把它接上路網(變成真中庭),
   接不上就一格一格改綠化。**一定要排在死路支線之前**:拆一塊 2×2 口袋會留下 L 形短枝,
   得讓階段 3 順手收掉(實測順序顛倒的話死路支線 45 → 47 格)。
3. **死路支線** —— 短枝先處理。① **接回成環**:沿支線找可鋪的裝飾鄰格改鋪成路
   (材質走 `matResolver`,跟旁邊的街道同材質);② **收枝**:長度 ≤ `maxStub` 的短枝
   整條改種綠化。

可動的地形是 `LOOP_PAVEABLE`(樹林／竹林／田埂路／花壇／映山紅／櫻花／松／巨石／特別樹)。
綠化材質取該街廓的 `ZONES.green`(若本身不可通行)→ 高地 `plateauGreen`(櫻花)→ `green`(樹林)。

**豁免(一格都不動)**:
- **幹道脊椎**(`spine`)與**鑿出來的跨水木棧橋**(`keep`) —— 主動線與唯一通路。
  (舊版還豁免「門前水泥廣場」,那個 pass 已隨分區優先架構移除。)
- **校門旁的通行格** —— 進出口,收掉會把門封死。
- **斜坡** —— 蓋上去高地就上不去了。
- 設定檔 `flow.exempt` 列出的座標。

**守衛與斷言**:每一步都要「景點一個不少、被包圍不變多、動線總分變小」才採用
(總分 = 孤立×100 + 走不到×20 + 死路支線格×3 + 死路端點,所以不可能「為了收枝而多兩個端點」);
跑完再斷言景點集合／包圍數／**水塘格數／斜坡集合全部沒變** —— 水塘與斜坡一格都沒動,
所以這個 pass 不可能破壞 `pond.maxCarve` 或高地動線。

`towns.js` 的參數:`flow: { loopify, check, maxStub, green, plateauGreen, sweeps, exempt }`。
沒宣告 `flow` 的鎮完全照舊(不跑 pass、verify 只出 INFO)。

**冬郵小鎮:舊版(湊景點優先)vs 現行(分區優先)**:

| | 舊版(已作廢) | **現行(分區優先)** |
|---|---|---|
| 通行格 | 313 | 262 |
| 孤立通行格 | 0 | **0** |
| 走不到的通行格 | 0 | **0** |
| 死路端點 | 10 | 21 |
| 死路支線 | 23(7%) | **56(21%)** |
| 景點／包圍／棟數 | 29/29・0・124 | 29/29・0・**143** |

**死路支線 7% → 21% 是取捨,不是退步。** 舊版那 7% 是拿原生地形買來的
(額外鑿 2 格水塘做東緣湖岸北橋、砍 1 棵櫻花＋2 棵樹林開坡口)。把同一份破壞清單
在新圖上重跑,**三組全部被自己的守衛退回**:東緣北橋動線總分 180 → 186(變差)、
西側櫻花坡 180 → 180、北丘西坡道 180 → 180(都沒變)。

反轉的原因:分區優先把建築密度從 124 拉到 143 棟,**死路支線的大宗變成「建築的唯一門面」**
—— 那是動線的目的地,不是缺陷。這種支線補環補不掉(橋接上去反而長出更多門面短枝),
所以「花原生地形換指標」的邊際效益整條歸零。`east.js` 的 `breakTerrain` 呼叫因此**整段移除**,
被退回的三組留在註解裡當帳。**143 棟房子有 143 個門口,門口本來就是路的終點。**

## 破壞地形補環(`builder.breakTerrain()`)—— 目前**沒有任何城鎮在用**

> **⚠ 冬郵改成分區優先後,這支的三組全部被守衛退回,`east.js` 已移除呼叫**(理由見上一節)。
> 函式本身保留:機制正確、守衛嚴格,將來哪個鎮真的有「花原生地形買動線」的划算機會時可以再用。
> 下面整段是**歷史帳與使用說明**,不是現行做法。

`carveWaterChannel()` 只認**可達面積增加**,所以它對「已經走得到、但只有單一出入口的盲腸」
一格都不會鑿(收益 0)。`breakTerrain()` 補這一塊:**明列座標、明說換到什麼、逐組驗收**。

```js
groups = [{ why: '一句話理由', cells: [[r, c, 'path'|'empty'], …] }]
```
- `'path'` → 破壞後鋪通行鋪面(材質交給後面的 `paveMaterials`／`keep`;列進 `keep` 的一律走廊＝木橋)。
- `'empty'` → 破壞後留空地。若這格在高地、四鄰剛好有低一階的格子,遊戲會**自動判成斜坡**
  → 多一個上坡口。跟 `openPlateaus()` 打通北丘是同一招,**不改任何 elevation**。
- 守衛(逐組):景點不能少、被包圍不能多、**動線總分必須真的變好**
  (`FLOW_COST` = 孤立×100 ＋ 走不到×20 ＋ 支線格×3 ＋ 端點,與 `loopify` 同一把尺)。
  整組跑完斷言 elevation 一格未動、原始斜坡一格未少。

**位置要排在環化 pass 之後**(`east.js` 的順序是 `paveMaterials → loopify → breakTerrain → loopify`)。
排在前面實測會失敗:東緣北橋的西側落點 `X15/Y5` 那時還是**不可通行的田埂路**
(要等 `loopify` 的「接回成環」才會補成走廊),橋接到沒補通的路上,動線總分反而 1061 → 1067,
被自己的守衛退回。**路網先定稿,破壞才知道該接哪裡。**

冬郵**舊版**採用的三組與當時就被否決的兩組(現在五組全部不採用):

## 解鎖階段:由校門向外一階一階長

`stages.js` 把每個 item 對到遊戲四階段(1 農村 → 2 發展 → 3 有望 → 4 名門)。
`DEV_GUIDE` 有收錄的照抄(`src: 'DEV_GUIDE'`,`cond` 也照抄);動物、挑戰獎勵
(金像／圖騰柱／宇宙火箭／開羅君系列)、環境磚是**手動推定**(`src: '推定'`),
頁面上要照實標「(推定)」。

- `spotStage(spot)` = req 每組先取「組內最早可用的選項」,再取全部材料的**最大值**
  (＝最晚必須等到的那一階)。目前分佈:1 階 6 個、2 階 5 個、3 階 12 個、4 階 6 個。
- `ZONES` 每區可宣告 `stage`。`design2.build()` 挑街廓時:
  **主排序仍是「要動的格數最少」**,同格數才比 `|spotStage − parcelStage|` 小者優先;
  硬規則＝`spotStage ≥ 3` 的景點不得把**新蓋的材料**放進 `stage === 1` 的街廓
  (已經有的材料共用不算),真的無處可放時會放寬並印
  `！階段硬規則放寬：…`。**29/29 與 0 包圍永遠優先於階段約束。**
- 沒宣告 `stage` 的街廓算**中立(懲罰 0)**,不是「差很多階」。這是刻意的:
  若讓未宣告的街廓吃懲罰,12 個 3 階景點會全部湧進南半部那幾個 stage 3 街廓,
  把分區要填的設施位擠光(實測健康鎮 29→28、棟數 147→115)。
- 因此各鎮的設定檔只在「真的要保護的開局核心」宣告 `stage: 1`
  (健康鎮＝西門玄關＋中央校舍／中央生活／舊操場帶;冬郵＝最北的舊校舍帶),
  其餘街廓只補 `name` 與 `mat`。
  冬郵把整個北半部都標成 stage 1／2 試過,棟數會掉到 108。

「階段 × 分區」對照表由 `gen-assets.js` **從分享碼反推**產生
(`stage-table-<town>.html`,欄位:階段／景點／所在分區／關鍵材料的解鎖條件),不手寫。
分區名的取法:一個景點常常在好幾個 4×4 窗口都成立,取「窗口左上角落在有名字的街廓、
而且街廓階段最接近景點階段」的那一個當代表;全都查不到就標「既有校舍／其他」。

## 冬郵小鎮的特殊處理

- **田埂路(`aze_path`)不可通行**,等同景觀;幹道會直接鋪過去,其餘留著當地形(77 格留 16)。
- **高地鋪滿草地／竹林時沒有斜坡**——`builder.openPlateaus()` 會貪婪地把邊界格
  「擦成空地」讓遊戲自動長出坡道,並窮舉短坡道鏈救援被圍住的既有建築。
- **不再破壞原生地形換動線**——`breakTerrain` 呼叫已從 `east.js` 移除(理由見上一節)。
  全圖只破壞 2 格水塘,而那 2 格是「不做就走不到」的必要工程:
- ### ★ 湖心島登島坡道:破壞水塘要「擦成空地」而不是「鋪成路」
  東南角有一塊陸地被水塘整圈圍住(上面有兩間原生養豬小屋)。麻煩的是
  **圍住它的那圈水塘記錄在 e2、島上平地是 e1** —— 把 e2 水塘鑿掉鋪成走廊,
  那格是「e2 的平地」,跟島上的 e1 差一階,**照樣走不過去**。
  而 `carveWaterChannel()` 只會把鑿開的格鋪成 `wood_path`(同高度才算通),
  所以它**找不到這條路**,只沿著 X21 那排 e1 往東打通 15 格就停手。

  解法是本管線的招牌手法:把 `X22/Y7`(r20,c20)與 `X23/Y7`(r21,c20)兩格 e2 水塘
  **擦成 `empty` 而不是鋪路** —— 空地只要旁邊有低一階的格子就自動判成**斜坡**,
  於是 `e1 → 斜坡 → 斜坡 → e1` 接成一道登島階梯,**一格 elevation 都沒改**。
  做在 `prepare()` 裡(`parcels()` 之前),島才會被切成正常街廓。

  > **⚠ 這裡抓到一個真 bug,已修(見下面「可達性的三個條件」)。**
  > 初版在島上放了電腦室與熊貓,兩個都通過驗證、實機卻走不到。
- **島上的稀有動物要 `preplace` 卡位**。島上只有 6 格平地,而 4×4 景點窗口罩得到那裡 ——
  不卡位的話「名門」(銅像＋金像＋電腦室)會吃掉 3 格,整座島只剩一隻熊貓(實測)。
  熊貓／無尾熊／鱷魚**都不是任何景點的材料**,釘死零風險,「名門」會自己搬去別的窗口。
- **教室與「學習／選舉」三件套也要 `preplace`**。教室不是任何景點的材料,
  景點骨架沒有理由蓋它 —— 放著不管整張圖只剩 1 間(原生那間)。
  「學習」(校長室＋圖書室＋多媒體)與「選舉」(校長室＋辦公室＋茶室)共用全校唯一的校長室,
  6 棟必須同框在一個 4×4 窗口,交給分區填充會被景點骨架先佔掉。

## 百靈山丘:全站唯一「29/29 全靠手放」的圖(2026-08 分區優先重做)

百靈是五鎮裡地形最極端的一張:**兩張互不相通的動線網**、全圖只有 16 格 e2、
初始校園整組坐在對低地全是 2 層懸崖的高台上。重做前的舊圖名目 29/29,正確重算卻是
**5 棟被包圍、7 座多格建築鋪不滿**(設施尺寸大修正後才現出來的帳)。

### ★ 為什麼這一鎮的景點骨架整組關掉

`hill.js` 的 `HAND_PLACED` 直接吃下 `E.SPOTS` 全部 29 個 id,`design2.build()` 拿到的
`spotOrder` 是空陣列 —— **全站唯一完全不用自動排版的鎮**。理由是幾何:

- 兩張網各有自己的門,`parcels()` 切出來的街廓橫跨高台與低地,但 design2 的窗口
  只掃「有 e1 可用格的街廓」,**看不到高台上的原生設施**,所有崖下借位窗都湊不出來。
- design2 挑街廓的次鍵是「要動的格數最少」,於是同格數的組合永遠落在先掃到的西側街廓
  (舊圖實測:熱血 3 棟蓋進農牧園區、生物蓋進名門區、時尚蓋進專科館)。
- 本鎮每一組景點的落點都是**幾何上唯一**的(見下四條),寫死之後圖與註解一一對應、可稽核。

代價是設定檔長,好處是**分區語意妥協從 7 棟降到 3 棟**(見文末)。

   音樂／理科／電腦全是 2×2 = 20 格,加焚化爐／飼育鼴鼠／銅像／金像 4 格再加一條 4 格橫廊
   剛好 28 —— 全圖沒有第二個街廓對做得到。三個互相錯開的 4×4 窗口一次成立
   **藝術・怪談・生物・名門**四個景點(rows8–11／rows10–13／rows11–14,都在 c10–13)。
2. **黃昏只能貼中央山丘南緣**。全圖 24 格斜坡都在中央山丘,而 4×4 窗口要同時容納
   一座 2×2 棒球場 → 只有 W(20,15)(rows20–23 × c15–18)辦得到:r20 的三格 e2 斜坡在窗內,

### ★ 崖下借位的正確規則:窗口可以跨崖,動線必須同高

4×4 景點窗口**不看高度也不看可達性**,所以「崖下開窗借高台材料」完全合法(本鎮初始 9 棟
一棟不拆、全部借出去用)。但**建築的出入口必須同高**——舊圖的校長室 `X12/Y4`、
多媒體教室 `X12/Y3`、餐廳 `X14/Y8` 拿「隔著 2 層懸崖的高台走廊」當門面,`canStep` 修對之後
就是 3 棟實機走不到。這一版把整條崖下行政帶的門面改成崖下同高的 c19／c24 縱街與 AV r15,
問題不必個案修正就消失了。

### ⚠ `blockedBuildings()` 把相鄰同型建築當一棟 —— 兩處要自己防

`engine.blockedBuildings()` 用 flood fill 把**同型且相鄰**的格子併成一棟,只要整片有一格
臨街就算「有出入口」。教室改成 2×2 之後 `11,0` 那四間排在一起 → 四間連成一片,
即使 (11–12,0–1) 那間真的沒有門,verify 也是 PASS。本鎮踩到兩次:

- **教學區中排的 4 格橫廊 (10,0)–(10,3)** 是那間教室唯一的門面,但它從 (10,4) 進來就到底
  ＝一條 4 格死路支線,`loopify` 會整條收成花壇(守衛只看景點與 blocked,都沒變)。
  → 寫進 `towns.js` 的 `flow.exempt`。
- **(1,3)**:不釘成通路的話 (0,3) 那棟的四鄰是公告欄、水岸的洗手間與 (1,3),整個封死。
  → PREPLACE 一格走廊接到 (1,4) 縱街。
- **原生販賣機 (10,18)**(2026-08 滿編校舍):它的四鄰只有 (9,18) 走得到 —— (10,19) 是 2 層懸崖、
  (11,18) 是原生便利商店、(10,17) 是同型販賣機(同型不算門)。第二間辦公室一度手放在 (8–9,17–18),
  (9,18) 一被吃掉它就整棟封死。→ 辦公室改放 (8–9,14–15)。
  ※ 1×1 的設施才是真死角:`blockedBuildings()` 會把同型連片**依 w×h 切回一棟一棟**再檢查,
    所以 2×2 的相鄰教室驗得出來;1×1 併成一片之後互相不算門、整片只要一格臨街就 PASS。

排完之後用「逐棟依 w×h 貪婪切塊、逐塊檢查出入口」的臨時腳本複驗過:**無出入口 0 棟**。
這是 verify 目前抓不到的一類問題,新增或搬動 2×2 建築時要自己再算一次。

### ★ 滿編校舍:9 間教室 ＋ 2 間辦公室(2026-08 硬指標)

遊戲裡 1～3 年級各開 3 個班 → **教室固定 9 間**;**辦公室上限 2 間**。兩者都不是景點材料,

## 溪谷小鎮的七個特殊處理(2026-08 分區優先重做)

溪谷是五鎮裡唯一的**三層地形**(谷底 e1 292 格／台地 e2 220 格／高地 e3 164 格,
高差 2 的斷崖 52 條),所以它踩到的坑跟其他四鎮完全不同:

- ### ★ 幾何事實先於分區設計:e1 只有三列深
  溪谷的 e1 被台地切成三條**只有 3 列可用**的帶(谷底 r10–r12、南平原 r16–r18、r22–r23),
  而 `parcels()` 只從 e1 空地切街廓。**一個 4×4 窗口要塞三座 2×2 就需要 4 列**,
  全圖只有兩個街廓做得到:`'20,0'`(rows20–23 × c0–c3,因為 r22c3/r23c3 也是 e1)與
  `'20,10'`(rows20–23 × c10–c13,因為 r20c12/c13 也是 e1)。「熱血」(足球場＋體育館＋
  游泳池)與「藝術」(美術室＋音樂室＋多功能室)剛好各要一個 → **一個給水泥地運動區、
  一個給走廊教學區**。所以溪谷的運動園區落在西南角而不是地圖中央,是這個幾何算出來的。
  初版把運動放 R3 那一列、教學給 `'20,10'`,結果 3×2×2 的景點全部擠不進走廊分區,

### ★ 為什麼只有 23/29:2×2 額度是硬牆

設施尺寸大修正後,湖岸的**南校區只排得下 11 座 2×2**(rows 15–19 幾乎被原生校舍、原生走廊
與水面佔滿),北岸帶那兩列 e1 平地被 **8 株 e3 樹墩**打斷、`fill` 的象限對齊規則下幾乎排不出
2×2。放棄的六個(藝術／家庭／時尚／燒水／澀谷／名門)**全部卡在同一件事**:要嘛「兩三座
2×2 同框」,要嘛「運動 2×2 與室內 2×2 同框」。硬湊的唯一辦法是把專科教室拆散塞進農牧區與
運動區 —— 那正是分區優先要避免的事,所以 `towns.js` 宣告 `spots.target: 23`,子頁逐個交代
放棄理由與「硬湊要付什麼代價」。

### ★ 把運動園區搬上北高地(本次最大的架構改變)

`fillPlateau` 逐格放置、2×2 會被 `sizeOf` 判掉,所以高地上長不出大型設施 —— 但**手放可以**。
北高地西半有 80 格以上連續的 e2 空地,南緣 `r6` 幾乎整列是原生斜坡(天生走得上去),於是
足球場＋體育館＋游泳池②(熱血)、操場＋籃球場＋販賣機(運動)、道場＋社團教室＋彈跳床
(動作)、足球場＋籃球場＋焚化爐(熱情)、棒球場＋`r6` 斜坡＋(3,8) e3 樹林(黃昏)
**五個景點全部在同一個分區成立**,完全不佔南校區的 2×2 額度。踩到的兩個坑:

1. **高地的動線要自己鋪**。`fillPlateau` 的步道規則是「每一列剩下的空地取最外側兩格」,
   手放的 2×2 橫在中間就會生出**上下不相通的口袋**:初版 rows0–1 整片被切斷,8 格步道被
   `tidyUnreachable`＋`landscapeDeadPockets` 判成假動線種了櫻花,體育館直接變成走不到。
   解法是先手鋪一副骨架 —— **`c1`(rows1–5)縱走道 ＋ `r1`(c1–c9)橫走道**,而且**直接鋪
   `concrete`**(高地步道不吃街廓投票,`paveMaterials` 只取鄰格步道的多數決,自己指定最準;
   順手把水泥地從 7 格拉到 20 格)。兩株 e3 樹 (0,3)/(1,5) 決定了骨架的 Z 字形狀。
2. **`design2` 看不到高地 → 會把同一個景點重蓋一次**。街廓只從 e1 空地切出來,所以
   `typesInWindow` 掃不到高原上已經蓋好的材料,`design2` 會在南半部再排一組(實測「動作」
   重蓋在北岸農牧帶 3 棟蓋錯區、「非洲」重蓋在舊校舍 2 棟)。解法是 `lake.js` 的
   **`HAND_PLACED`**:把手放到位、已經成立的景點整個**排出 `spotOrder`**,
   `D.build(B.spotOrder().filter(...))` —— design2 的預算就全留給還沒成立的景點。
   ※ 這是本管線第一次出現「手放 + 排除」的組合,其他鎮若要在高地上做景點,照抄這一招。
