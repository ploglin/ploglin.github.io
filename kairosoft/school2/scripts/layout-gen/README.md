# 完美佈局產生管線(內部工具)

產生並驗證各城鎮的「完美佈局」(layouts/ 頁上 29 景點全成立的地圖)。
設施尺寸、SPOTS、地形都**直接從 ../../sim/index.html 抽取**,模擬器資料改了重跑即可。

目前已產出:**健康鎮 26×24**(`health-perfect.svg`)、**冬郵小鎮 26×26**(`east-perfect.svg`)、
**百靈山丘 26×26**(`hill-perfect.svg`)、**溪谷小鎮 26×26**(`valley-perfect.svg`)與
**湖岸小鎮 24×24**(`lake-perfect.svg`),五張都是 29/29 景點、0 棟被包圍。
五張也**全部**照新優先序「**動線流暢優先於景點配置**」重排過(冬郵是先例):
孤立通行格全部 0,死路支線占比 **冬郵 7%**／百靈 7%／健康 10%／溪谷 13%／湖岸 18%
(見「動線流暢優先」一節;占比差異是地形決定的,刻意不設一刀切門檻)。
冬郵另外是**唯一開放「破壞原生地形換動線」**的鎮(`builder.breakTerrain()`,手挑清單):
鑿 4 格水塘 ＋ 砍 3 格原生植栽,把死路支線從 15% 再壓到 7%(見「冬郵的破壞地形補環」一節)。

## 檔案

| 檔案 | 角色 |
|---|---|
| `towns.js` | **城鎮設定表**(尺寸／preset 變數名／SVG 檔名／`page` 子頁目錄／`pond.maxCarve` 水塘破壞預算／棋盤路網參數／`spine` 幹道脊椎／`flow` **動線環化開關**)。唯一的「哪個城鎮」開關。 |
| `engine.js` | 從 sim 抽 items/SPOTS/該鎮地形,複製判定邏輯(4×4 景點、斜坡推導、可達性 BFS、包圍判定、**動線指標 `flowMetrics`**、分享碼 encode/decode)。 |
| `stages.js` | **解鎖階段對照表**:item id → 遊戲四階段(1 農村／2 發展／3 有望／4 名門),來源標 `DEV_GUIDE` 或 `推定`。輸出 `itemStage()`／`itemCond()`／`spotStage()`／`spotKeyItem()`。 |
| `design2.js` | 路網佈局器:鋪路 → 切 4×4 街廓 → 街廓填景點骨架(唯一設施不重複、整組放置有包圍守衛、**街廓階段偏好**)。 |
| `builder.js` | **城鎮無關的共用機具**:4×4 補位、分區填充、綠化、加開校門、**鑿水道**、打通高地坡道、**破壞地形補環 `breakTerrain()`**、高地開發、斷頭路整理、**材質重鋪 pass**、**環化 pass**(動線)、驗證輸出。 |
| `final.js` | 健康鎮的**設定檔**(街廓分區＋`stage`／`mat`、校長室位置、第二座校門、高地園區)。 |
| `east.js` | 冬郵小鎮的**設定檔**。 |
| `hill.js` | 百靈山丘的**設定檔**(高台手放清單 `PREPLACE`、田埂路覆蓋、南門、孤立口袋景觀化)。 |
| `valley.js` | 溪谷小鎮的**設定檔**(開局 `ERASE` 3 格、台地肩／星空台／開羅廣場的 `PREPLACE`、坡道保留帶斷言、走不到的草地口袋景觀化)。 |
| `lake.js` | 湖岸小鎮的**設定檔**(24×24;鎖喉走廊保護格、清一格 e2 樹墩「長出」踏石橋、被湖圈死的鱷魚池拆遷、六個街廓整組 `PREPLACE`、北高地切四條縱帶 `fillPlateau`、走不到的草地口袋景觀化)。 |
| `verify.js` | **可重跑的驗證器**,只吃分享碼(含動線指標 INFO 與 `flow.check` 開的孤立格 PASS)。 |
| `gen-assets.js` | 由分享碼產生 `layouts/*.svg`(含鋪面圖例)與頁面要用的表格 HTML(景點座標／設施統計／**階段 × 分區**)。 |

(`zones-*.json` 由 `final.js`／`east.js` 寫出,是 `gen-assets.js` 產「階段 × 分區」表的唯一分區來源

## 佈局頁的結構

```
layouts/index.html          完美佈局 hub:城鎮卡片 + **共用的設計原則(只寫一次)** + 入門小範例
layouts/<town.page>/        各鎮子頁:地圖 / 分享碼 / 統計 / 景點座標表 / 設施表 / 施工順序
layouts/*-perfect.svg       兩鎮共用同一層的 SVG(子頁以 ../xxx-perfect.svg 引用)
```

各鎮子頁頁首有一排**城鎮切換 pills**(連到兄弟頁,現在所在鎮標 `.on`),
擴充到五鎮時只要在 pills 清單加一筆。子頁是**巢狀 slug**(`layouts/<鎮>/`),
`scripts/gen-game-nav.js` 只掃遊戲根目錄的第一層,所以**不會**進遊戲功能列
(也不必登記 LABELS、不會出現未知 slug 警告);橫向切換由 pills 與 hub 負責,
麵包屑則是「口袋學院物語2 → 佈局範例集 → ○○鎮完美佈局」。
`scripts/gen-related.js` 的 `RELATED` 已登記 `layouts/health` / `layouts/east`
(巢狀 key,href 要多退一層)。新增城鎮頁後重跑 `node scripts/gen-related.js`
與 `node scripts/gen-sitemap.js`。

把 `code-*.txt` 貼進該鎮子頁的「在模擬器開啟」按鈕、表格 HTML 貼進對應
`<tbody>`,然後**一定要跑 `node verify.js <town> page`**——它直接從該鎮子頁
抓分享碼解碼重驗,確保頁面上的圖就是驗過的那張。全部 PASS 才算完成。

## 加一個新城鎮

1. `sim/index.html` 要有該鎮的 `PRESET_XXX_DATA`(並鏡射到 `sim/presets/`)。
2. `towns.js` 加一筆:`rows`/`cols`(= 座標上限 − 1)、`preset` 變數名、`svg` 檔名、
   `page`(子頁目錄名)、`pond.maxCarve`(允許破壞幾格水塘)、
   `roads`(橫向大道列、縱向街道欄、街廓帶——街廓寬高盡量對齊 4,因為 4×4 就是景點窗口)、
   `spine`(幹道脊椎:把兩座校門串起來的 1 橫 1–2 縱,材質重鋪 pass 會鋪成道路)、
   `flow`(動線環化開關;**重排完、確認孤立通行格已經是 0 才開 `check: true`**)。
3. 抄 `east.js` 當範本,只改分區設定(每區都要有 `stage` 與 `mat`);**不要複製 engine/builder**。
4. `verify.js` / `gen-assets.js` 的 `CODE_FILE` 對照表加一行。
5. 新增 `layouts/<page>/index.html`(抄現有子頁,head 靜態手寫 SEO)、
   把該鎮加進 hub 的城鎮卡片與所有子頁的 pills 清單,
   再跑 `node scripts/gen-related.js` 與 `node scripts/gen-sitemap.js`。

> ⚠️ 進入點腳本**必須**在 `require('./engine.js')` 之前先 `require('./towns.js').select(key)`——
> engine 與 design2 會在載入當下把 `gridRows`/`gridCols` 解構成常數。

## 產生器的固定假設(頁面上也要照這樣說明)

- **水塘可以破壞,但要有預算**:實機確認**水塘可被建設覆蓋、破壞成平地**(保留原高度)。
  `towns.js` 的 `pond.maxCarve` 是該鎮允許破壞的格數**總上限**,`verify.js` 檢查
  「破壞數 ≤ 上限」「沒有無中生有的新水塘」「鑿開的格子保持原高度」,並列出破壞座標。
  破壞分兩筆帳,設定檔要分開給預算:`pond.channel` 給 `carveWaterChannel()`(接進走不到的陸地)、
  差額給 `breakTerrain()`(補動線環)。目前:健康鎮 0 格、
  **冬郵小鎮 4 格**(`channel: 2` 東南湖心水道 ＋ 2 格東緣湖岸北橋)、百靈山丘 0 格(水面全記在 e3,鑿了也只剩孤格)、
  溪谷小鎮 0 格、**湖岸小鎮 0 格**(146 格湖面全保留 —— 山中湖記在 e3、東北角湖只圈住 2 格空地,
  鑿了都沒有收益;真正要打通的南北動線改用「清一格 e2 樹墩長出斜坡」解決,見下)。
- **原始斜坡一格不動**:斜坡是高低差推導出來的,蓋東西上去高地就上不去了。
  反過來,**新增斜坡是合法手段**:把高地上的植栽／草地「擦成空地」遊戲就會自動判成斜坡
  (`openPlateaus()` 打通高地、`breakTerrain()` 開捷徑都靠這招)。任何情況下
  **elevation 一格都不准動**——`breakTerrain()` 跑完會斷言 elevation 簽章與原始斜坡集合。
- **既有校舍原則上保留**;只有卡在幹道上的小農舍(小雞／小農場／田地／百葉箱)
  與「怎麼蓋都走不到」的建築會拆遷,並在別區重建。`verify.js` 會把拆掉的清單印出來。
- **高地可以蓋房**,每列最外側留步道接坡道;步道材質由 `fillPlateau` 的 `walkMat` 決定
  (公園類高地＝草地小徑、設施類園區＝走廊)。
  `fillPlateau` 是**逐格放置**,多格設施會被 `sizeOf` 判掉並跳過 → **`zone.fac` 只能列 1×1**。
  設施改尺寸(例:游泳池／體育館 1×1 → 2×2)時要回頭清掉高地清單裡的那一項,
  不然它每輪白佔一個位置、那格只會被綠化掉(健康鎮東高地曾因此從 16 棟掉到 12 棟)。
- **不放 `hidden` 磚**(例如 `slope`),地圖上不能有玩家蓋不出來的東西。

## 動線材質:四種鋪面各有語意

**不再全圖一律鋪走廊。** 遊戲的四種通行鋪面都屬可通行、都不是任何景點的負材料
(只有草地本身是景點材料),所以材質可以自由分配,並且分配得有意義:

| 鋪面 | 日文 | 語意與依據 | 用在哪 |
|---|---|---|---|
| 道路 `asphalt` | 外通路 | 室外幹道;道具「滑板」在道路與草地加速 | **幹道脊椎**(兩座校門的動線＋中軸)、農牧／公園／湖心／池畔外的自然帶 |
| 走廊 `wood_path` | 木造廊下 | 校舍內廊道;「抹布」在此加速,「相機組／寫生」按走廊算打工收入 | 教學核心、生活機能、舊校舍、運動園區的街道;鑿出來的**水道橋**(木橋意象) |
| 水泥地 `concrete` | パネル廊下 | 硬鋪面;**機制未確認、純美觀** | 只當體育館／泳池／道場的**門前廣場**(1–2 格),不當通道 |
| 草地 `grass` | 芝生 | 自然小徑,同時是菜園／力量／清爽的材料 | 分區內部填充、公園類高地步道 |

實作是產生管線最後的重鋪 pass:`builder.paveMaterials(g, { zones, spine, keep })`,
在 `report()` 之前跑。它只改「已經是道路格、且 elevation === 1」的格子:

- `spine`(`towns.js` 宣告的列／欄)一律鋪**道路**。
- 其餘街道段看「鄰接街廓的 `ZONES.mat`」;一段路兩側 mat 不同時取優先序 **道路 > 走廊**。
- `keep`(`carveWaterChannel` 回傳的水道格)保持走廊。
- 高地步道(elevation > 1)不動,由 `fillPlateau` 的 `walkMat` 決定。
- 門前廣場照樣走 `guarded()`(景點不可少、包圍不可多),失敗就跳過;幹道與水道橋不動。

這個 pass **必須是景點中立的**:跑完會用 `activeSpots` / `blockedBuildings` 斷言
(景點一個都不能少、被包圍建築不能變多),不中立就直接 throw。

驗收門檻:**四種鋪面皆 > 0、走廊 ≤ 四種合計的 60%**。
目前健康鎮 走廊 102／道路 87／水泥地 14／草地 53(走廊 40%、148 棟 —— 套過環化 pass 的數字),
冬郵小鎮 走廊 81／道路 82／水泥地 16／草地 100(走廊 29%、124 棟 —— 套過環化 pass ＋ 破壞地形補環的數字),
百靈山丘 走廊 67／道路 124／水泥地 4／草地 159(走廊 19%、157 棟 —— 套過環化 pass 的數字),
溪谷小鎮 走廊 26／道路 77／水泥地 10／草地 112(走廊 12%、150 棟 —— 套過環化 pass 的數字;
谷底能鋪的街道本來就只有那幾條),
湖岸小鎮 走廊 27／道路 64／水泥地 4／草地 78(走廊 16%、116 棟 —— 套過環化 pass 的數字;
全圖最小、水最多,分母本來就小)。
(游泳池／體育館依實機回報改成 2×2 後重算的數字;水泥門前廣場兩鎮都變成 12 處,
因為 2×2 的門面比 1×1 寬。)

## 動線流暢優先於景點配置:環化 pass

**新的設計優先序**:29/29 景點與 0 棟被包圍仍是硬指標,但兩者達成之後還要顧
**路網本身好不好走**;實務上兩者大概率不衝突,只有真二選一時才讓景點。
舊管線只驗「每棟走得到」,於是留下兩類沒有動線價值的格子:

1. **走不到的假路面** —— 街廓綠化把剩餘空地鋪成 `grass`,而草地是**可通行**的,
   四面被建築圍住的那格就變成誰也走不進去的假草皮;更隱性的是「度數都 ≥ 2、
   整塊卻接不到校門」的 2×2 中庭(看起來是條路)。
2. **死路支線** —— 從度 1 端點走到第一個岔路口的那一段,走進去只能原路折返。

### 指標定義(`engine.flowMetrics(g)`,verify 與 builder 共用一份)

| 名稱 | 定義 |
|---|---|
| 度數 | 四鄰中 `canStep` 走得過去的**通行格**數。**校門算一度**(gate 不在 `PASSABLE`,但它就是進出口,不然門前那格會被誤判成死路) |
| 孤立通行格 | 度 0 的通行格。**視同缺陷** |
| 走不到的通行格 | 從任一校門 BFS 到不了的通行格(孤立格是其特例) |
| 死路端點 | 度 1 的通行格 |
| 死路支線 | 每個端點沿唯一路徑走到第一個度 ≥ 3 節點,路上的格(多端點共用只算一次) |
| 占比 | 死路支線格 / 通行格 |

`verify.js` 每張圖都印這幾個數字當 **INFO**;**「孤立通行格 = 0」是 PASS 檢查**,
由 `towns.js` 的 `flow.check` 開關控制 —— 只有已重排的鎮才開,**五鎮現在全部開了**。
**死路占比刻意不設門檻**:五鎮地形差太多
(百靈山丘環化後 7%、湖岸小鎮環化後仍有 18%,是湖面與斷崖決定的),一刀切只會逼出爛決策。

### `builder.loopify(g, opts)`

跑在 `paveMaterials` **之後**、`report` 之前。三個階段依缺陷嚴重度排,
**整組重跑到收斂**(`sweeps`,預設 3):

1. **孤立通行格** —— 先試「接回路網」(只認接完**度 ≥ 2** 的,不然只是把死路挪一格),
   不行才改種綠化。
2. **假動線口袋**(走不到但度 ≥ 2) —— 先試鋪一格裝飾把它接上路網(變成真中庭),
   接不上就一格一格改綠化。**一定要排在死路支線之前**:拆一塊 2×2 口袋會留下 L 形短枝,
   得讓階段 3 順手收掉(實測順序顛倒的話死路支線 45 → 47 格)。
3. **死路支線** —— 短枝先處理。① **接回成環**:沿支線找可鋪的裝飾鄰格改鋪成路
   (材質走 `matResolver`,跟旁邊的街道同材質);② **收枝**:長度 ≤ `maxStub` 的短枝
   整條改種綠化。

可動的地形是 `LOOP_PAVEABLE`(樹林／竹林／田埂路／花壇／映山紅／櫻花／松／巨石／特別樹)。
綠化材質取該街廓的 `ZONES.green`(若本身不可通行)→ 高地 `plateauGreen`(櫻花)→ `green`(樹林)。

**豁免(一格都不動)**:
- **門前水泥廣場** —— 體育館／泳池／道場旁的 `concrete` 是建築門面,天生是端點。
- **幹道脊椎**(`spine`)與**鑿出來的水道橋**(`keep`) —— 主動線與唯一通路。
- **校門旁的通行格** —— 進出口,收掉會把門封死。
- **斜坡** —— 蓋上去高地就上不去了。
- 設定檔 `flow.exempt` 列出的座標。

**守衛與斷言**:每一步都要「景點一個不少、被包圍不變多、動線總分變小」才採用
(總分 = 孤立×100 + 走不到×20 + 死路支線格×3 + 死路端點,所以不可能「為了收枝而多兩個端點」);
跑完再斷言景點集合／包圍數／**水塘格數／斜坡集合全部沒變** —— 水塘與斜坡一格都沒動,
所以這個 pass 不可能破壞 `pond.maxCarve` 或高地動線。

`towns.js` 的參數:`flow: { loopify, check, maxStub, green, plateauGreen, sweeps, exempt }`。
沒宣告 `flow` 的鎮完全照舊(不跑 pass、verify 只出 INFO)。

## 冬郵的破壞地形補環(`builder.breakTerrain()`)

`carveWaterChannel()` 只認**可達面積增加**,所以它對「已經走得到、但只有單一出入口的盲腸」
一格都不會鑿(收益 0)。`breakTerrain()` 補這一塊:**明列座標、明說換到什麼、逐組驗收**。

```js
groups = [{ why: '一句話理由', cells: [[r, c, 'path'|'empty'], …] }]
```
- `'path'` → 破壞後鋪通行鋪面(材質交給後面的 `paveMaterials`／`keep`;列進 `keep` 的一律走廊＝木橋)。
- `'empty'` → 破壞後留空地。若這格在高地、四鄰剛好有低一階的格子,遊戲會**自動判成斜坡**
  → 多一個上坡口。跟 `openPlateaus()` 打通北丘是同一招,**不改任何 elevation**。
- 守衛(逐組):景點不能少、被包圍不能多、**動線總分必須真的變好**
  (`FLOW_COST` = 孤立×100 ＋ 走不到×20 ＋ 支線格×3 ＋ 端點,與 `loopify` 同一把尺)。
  整組跑完斷言 elevation 一格未動、原始斜坡一格未少。

**位置要排在環化 pass 之後**(`east.js` 的順序是 `paveMaterials → loopify → breakTerrain → loopify`)。
排在前面實測會失敗:東緣北橋的西側落點 `X15/Y5` 那時還是**不可通行的田埂路**
(要等 `loopify` 的「接回成環」才會補成走廊),橋接到沒補通的路上,動線總分反而 1061 → 1067,
被自己的守衛退回。**路網先定稿,破壞才知道該接哪裡。**

冬郵採用的三組(方案 D)與被否決的兩組:

## 解鎖階段:由校門向外一階一階長

`stages.js` 把每個 item 對到遊戲四階段(1 農村 → 2 發展 → 3 有望 → 4 名門)。
`DEV_GUIDE` 有收錄的照抄(`src: 'DEV_GUIDE'`,`cond` 也照抄);動物、挑戰獎勵
(金像／圖騰柱／宇宙火箭／開羅君系列)、環境磚是**手動推定**(`src: '推定'`),
頁面上要照實標「(推定)」。

- `spotStage(spot)` = req 每組先取「組內最早可用的選項」,再取全部材料的**最大值**
  (＝最晚必須等到的那一階)。目前分佈:1 階 6 個、2 階 5 個、3 階 12 個、4 階 6 個。
- `ZONES` 每區可宣告 `stage`。`design2.build()` 挑街廓時:
  **主排序仍是「要動的格數最少」**,同格數才比 `|spotStage − parcelStage|` 小者優先;
  硬規則＝`spotStage ≥ 3` 的景點不得把**新蓋的材料**放進 `stage === 1` 的街廓
  (已經有的材料共用不算),真的無處可放時會放寬並印
  `！階段硬規則放寬：…`。**29/29 與 0 包圍永遠優先於階段約束。**
- 沒宣告 `stage` 的街廓算**中立(懲罰 0)**,不是「差很多階」。這是刻意的:
  若讓未宣告的街廓吃懲罰,12 個 3 階景點會全部湧進南半部那幾個 stage 3 街廓,
  把分區要填的設施位擠光(實測健康鎮 29→28、棟數 147→115)。
- 因此各鎮的設定檔只在「真的要保護的開局核心」宣告 `stage: 1`
  (健康鎮＝校門廣場;冬郵＝最北的舊校舍帶),其餘街廓只補 `name` 與 `mat`。
  冬郵把整個北半部都標成 stage 1／2 試過,棟數會掉到 108。

「階段 × 分區」對照表由 `gen-assets.js` **從分享碼反推**產生
(`stage-table-<town>.html`,欄位:階段／景點／所在分區／關鍵材料的解鎖條件),不手寫。
分區名的取法:一個景點常常在好幾個 4×4 窗口都成立,取「窗口左上角落在有名字的街廓、
而且街廓階段最接近景點階段」的那一個當代表;全都查不到就標「既有校舍／其他」。

## 冬郵小鎮的四個特殊處理

- **田埂路(`aze_path`)不可通行**,等同景觀;幹道會直接鋪過去,其餘留著當地形。
- **高地鋪滿草地／竹林時沒有斜坡**——`builder.openPlateaus()` 會貪婪地把邊界格
  「擦成空地」讓遊戲自動長出坡道,並窮舉短坡道鏈救援被圍住的既有建築。
- **允許破壞原生地形換動線**——見上面「冬郵的破壞地形補環」一節(五鎮裡只有冬郵開)。
- **東南角有 39 格陸地被水塘圍住**——`builder.carveWaterChannel()` 用 0-1 Dijkstra
  (經過水塘 +1)算出最省的水道,實際模擬後挑「打通面積最大、破壞格數最少」的那條。
  冬郵只鑿 `X21/Y5`、`X21/Y4` 兩格就打通 15 格動線,**島上兩間原生養豬小屋原地保留**;
  鑿通後的湖心區被規劃成 **stage 4 的「後期動物島」**——熊貓／無尾熊／鱷魚
  (＋原本擺在西側的稀有動物)搬到島上,基礎農牧留西側。
  這四種稀有動物**都不是任何景點的材料**,所以搬島對 29/29 完全零風險;
  但島上平地只有 3 格排得下建築,第 4 隻(長頸鹿)退回西側農牧園區。

## 百靈山丘的六個特殊處理

- **兩張互不相通的動線網**。整個初始校園在東北高地(elev3),對低地全是 2 層落差的懸崖;
  全圖僅有的 16 格 elev2 在正中央小山丘,跟高台不相鄰,所以 `openPlateaus()` **一格坡道也開不出來**
  (擦成空地後鄰格差 2,推導不出斜坡),本鎮不呼叫它。高台網靠既有東門、低地網靠自己加的南門,
  可達性取「所有校門的聯集」→ 全圖 0 包圍。**這一點需要實機確認**(見子頁的誠實說明段)。
- **開局就有 4 棟被田埂路圈死**(gym / tennis×2 / basketball)。`layRoads()` 只鋪 `elevation === 1`,
  所以高台的 18 格 `aze_path` 得在 `prepare()` 裡自己覆蓋成走廊(沿用原高度),否則永遠 4 棟走不到。
- **南門要在 `prepare()` 裡加,不能等到 `fill` 之後**。`parcels()` 是用可達性決定哪些格是
  「可蓋建築的 slots」,低地沒門的話整片會被判成 green(只能種草),design2 一棟都放不下。
  (冬郵可以在 fill 之後才 `addGate`,是因為它的低地本來就被北門服務到。)
- **崖下借位窗 → 大量 `preplace`**。4×4 景點窗口不看高度也不看可達性,所以把新建築蓋在崖下、
  讓窗口罩住高台的舊校舍,就能白拿一件材料(初始 9 棟全部沿用、拆除 0)。
  但 design2 的街廓填充只會在街廓內找「格數最少」的位置,湊不出這種跨崖窗口,
  所以熱血／選舉／學習／宇宙／購物／特盛／吃醋／澀谷＋高台北園 7 棟全部走 `PREPLACE` 手放。
  另外三組(水岸／力量／埋伏／菜園／好友・家庭・燒水)也手放,原因不同——
  **水岸需要水塘,而 design2 找不到「零成本窗口」時會自己蓋一格水塘**,那會踩到
  verify 的「沒有無中生有的新水塘」。把材料釘在現成水塘旁邊讓它掃到 `cells = 0` 就不會造水。
- **孤立口袋要在 `parcels()` 之前先種樹封起來**。包圍判定只看「鄰格可通行且從任一校門走得到」,
  **不看高低差**,所以隔著 2 層懸崖鄰接高台走廊的口袋會出現「判定合格、實際走不到」的假通過
  (實測不封的話 design2 會把音樂室／理科室排進東緣口袋)。`hill.js` 的 `landscapeDeadPockets()`
  在 prepare 與收尾各跑一次;`elevation > 1` 的原生高地草坡刻意不動(它是水岸／力量的窗內材料)。
- **環化 pass 的豁免清單必須整片點名西北高地草坡**(rows1–5 × c6–10 的 16 格 elev3 草地,
  即「走不到的通行格 16」的全部來源)。它懸崖圍死、玩家上不去,是頁面明文保留的景觀窗
  兼水岸／力量的窗內材料;但 loopify 的守衛**只保「景點不能少」**,力量的窗口用不到的那幾格草
  會被 fixPockets 一格一格吃掉(unreach −20 分,cost 一定變好),所以要用 `flow.exempt` 釘死。
  低地 14 格孤立口袋不必列:它們已種樹封死(不可通行),flowMetrics 數不到;把封樹鋪回通行面
  也一定讓 unreach +20 分、過不了 cost 守衛。本鎮重排前就是五鎮死路占比最低(10%),
  環化後 41 → 25 格(**7%**)、端點 15 → 11,只動 13 格:接回成環 3 格(巨石＋花壇×2 → 道路,
  把西緣 6 格草徑與 c4 縱街北段接成環)、收枝 5 枝 10 格(高台北緣草徑→櫻花、行政高台
  2 格原生 asphalt 斷枝→櫻花、c4 頂端與一格假草皮→樹林)。29/29／0 包圍／157 棟／
  24 格斜坡／20 格水塘全部不變;唯一表面變化是「力量」的**代表窗口**從 W(0,5) 變 W(0,1)
  (收枝種出的樹林讓北西水岸區也湊出一組,verify 取先掃到的;跨崖借景窗照樣成立)。

## 溪谷小鎮的四個特殊處理

  (教室／養雞／辦公室／多媒體／公告欄／飼育鱷魚)。天然坡道 136 → 139。
  ※ `prepare()` 在 `layRoads()` **之後**執行,但 layRoads 只鋪 `elevation === 1`,
    所以這三格 e3 不會先被鋪掉,順序沒有問題。
- **坡道保留帶要自己斷言**:r13(X15)／r15(X17)是谷底↔南平原的兩排天然坡,r14(X16)是
  換坡平台,三列都在 e2。`layRoads` 與 `B.fill` 只吃 e1,所以天生碰不到;但
  `fillPlateau` 會 —— 只要把 r13–r15 放進任何一個高地區,一格草地就殺掉一整條坡道,

  可通行的換坡口 ③走不到的通行格 ≤ 15。第一版就是被 ① 擋下來的。

    臺地肩會多出 3–4 格死地(實測過)。
  ②**星空台**:東南丘丘頂只有 (22,24)(22,25) 兩格非坡格 → 宇宙火箭＋天象館;
    多媒體#2 放丘下 e2 的 (22,22)(23,22) —— 這樣街廓 `'25,25'` 的判定窗口(夾進地圖後
    = (22,22))剛好框住三件材料,design2 掃到「宇宙」時 missing 為空、**成本 0**,
    不會重複蓋第二座火箭。③**開羅廣場**同理,三件 1×1 落在街廓 `'20,20'` 的窗口內。
- **水塘一格都不能鑿,而且「水岸」要手放**:北池 6 格是水岸的材料;南池 10 格的**池面
  記錄在 e3、四周是 e1**,鑿掉只會留下對四鄰都是崖的 e3 孤柱(連走上去都做不到),
  所以 `pond.maxCarve = 0`。另外 `pond` 在 items 裡是可畫的環境磚,放手讓 design2 湊
  「水岸」它會**自己蓋一座新水塘**,verify 的「沒有無中生有的新水塘」就會 FAIL
  (實機也蓋不出水塘)—— 解法是把水井 (11,7) 與洗手間 (11,8) 手放在原生北池南岸,
  街廓 `'10,5'` 的窗口一次框住池水＋兩件設施。
- **原生的 15 格結構性死地整份列 `flow.exempt`**:舊校舍臺地上 8 格**原生走廊口袋**
  (被辦公室、多媒體與高差 2 的崖夾死,結構性無解)＋東緣 7 格**原生草地高地坡**,
  改鋪或改綠化都不會讓玩家多走到一格,只會把原生校舍與草坡的樣子改掉 —— 所以環化 pass
  一格都不准動它們。溪谷早期曾有兩段自家收尾(`tidyUnreachable` 刻意不跑＋自寫的
  `tidyPockets()` 把走不到的草地種成樹林),套用環化 pass 時**整段收編**:tidyPockets 的
  職責就是 loopify 的階段 B(假動線口袋),而 loopify 先試「接回路網」才綠化、守衛還多了
  動線總分,嚴格更強,不留兩套並存。

**階段宣告的結論跟冬郵相反**:冬郵把北半部標階段會掉棟數,溪谷把谷底與南半部一路標成
2／3／4 階反而從 **147 棟變 150 棟**(階段偏好只是同分時的 tiebreaker,把景點推去語意對的
街廓之後,各分區原本要填的設施位就空得出來)。**這件事要一鎮一鎮實測,不能照抄。**

驗收數字:溪谷 29/29、0 包圍、**150 棟**(高地上 45)、教室 4 間、校門 2 座、
走不到的通行格 15(舊校舍走廊口袋 8＋東緣草地高地坡 7,後者擦 (9,25) 一格即可復活,

X16 那條大道整列在 e2 上鋪不出來)。**環化 pass 前後**:死路端點 29 → 24、

## 湖岸小鎮的五個特殊處理

湖岸是五鎮裡**最小(24×24)、水最多(146 格 = 全圖 25%)**的一張,陸地只有 430 格。
`towns.js` 的 `rows`/`cols` 都是 24,`ROW_BANDS` 特意多切一條 `[0,4]`(北高地,全在 e2/e3、
沒有 e1 可用格 → `parcels()` 直接略過,純粹讓「階段 × 分區」表查得到分區名)。

- **南北鎖喉走廊只有兩格**:北半部(北高地＋北岸帶＋中央半島,約 245 格)與南半部校區之間
  天然只有 `r14` 的 `c4`–`c7`;其中 (14,4) 販賣機、(14,5) 飲水處是原生設施,**真正能走的
  只有 (14,6)、(14,7)**。它們落在 AV `r14` 上、`layRoads` 會鋪成路而自動受保護,但**北側
  銜接的 (13,6)/(13,7) 與踏石橋西橋頭 (13,13) 落在中央半島街廓裡**,必須用 `PREPLACE`
  手鋪 `wood_path` 釘住 —— 不釘的話 `B.fill` 會把音樂室／理科室蓋上去,北半部一次全斷
  (實測 5 棟同時變走不到)。同理 (15,6) 是鎖喉走廊唯一的南向出口,`ZONES['15,5']` 的
  生活棟建材全部手放、刻意繞開它。
- **清一格 e2 樹墩,遊戲自己長出斜坡橋**:`prepare()` 把 (13,14)(一格 e2 樹林,夾在
  (13,13)/(12,14)/(14,14) 三格 e1 之間)清成 `empty`。因為 `isSlope` 是**高低差推導**的,
  那一格立刻變成斜坡,e1↔e2↔e1 成為一座免費踏石橋:①打通「水井口袋」
  ((12,14)–(12,17)/(13,15)–(13,17) 七格＋原生水井 (13,18),開局是走不到的建築)
  ②多開一條南北通道。**這是「不鑿湖也能 29/29」的關鍵**,也是本管線第一次把
  「斜坡是算出來的」當**攻擊手段**而不是限制。水岸＋力量兩個景點因此只花 2 格新建
  (洗手間 (12,15)＋草地 (13,16)),搭原生水井、原生 e2 樹林 (12,18) 與山中湖水面,
  在同一個窗口 W(10,15) 成立 —— 五鎮最便宜的一組。
- **原生鱷魚池 (7,23) 被東北角湖圈死,只能拆遷**:四鄰是水塘與竹林,附近唯一的兩格空地
  (5,23)/(6,22) **彼此還是斜角、互不相鄰**,兩格自己也被湖包住 → 開局就是「被包圍的建築」,
  而 `maxCarve = 0`。`prepare()` 把它覆蓋成 `woods`,鱷魚連同熊貓／無尾熊在北高地重建成
  「高原動物園」(這三種都不是任何景點的材料,搬家零風險)。**這是五鎮裡唯一一棟拆遷。**
- **六個街廓的建材整組 `PREPLACE`**:東行政學術翼(13 格建材塞進 16 格,選舉＋學習同窗)、
  南商業街(餐廳＋便利商店兩座 2×2 就吃掉 8 格,購物＋特盛＋吃醋同窗)、稀有動物角＋宇宙區、
  泳池體育館區(熱血＋澀谷)、東校舍運動區(動作)、北岸運動帶(運動＋熱情共用籃球場)。
  這些窗口動輒 6–13 格,`design2` 的街廓填充排不出來(實測會把宇宙火箭、長頸鹿全丟到北岸)。
  手放時每一棟的臨路面都要逐格算:**滿滿一個 4×4 的建築區必定有內側格走不到**,
  學術翼因此把 `c23` 整欄留成走廊 —— 它同時是東岸步道(埋伏三件套)唯一的出路
  ((13,23)→(14,23)→(15,23)→r19),少一格就有 5 棟走不到。
- **北高地切四條縱帶**:`fillPlateau` 是「每一列只留最外側兩格當步道」,一條 20 格寬的
  橫帶會讓中間 18 棟互相圍死。切成 `cols [0,4]/[5,9]/[10,14]/[15,19]` 之後步道自然變成
  幾條縱向草徑,38 棟全部貼得到路。北高地南緣 `r6` 幾乎整列都是**原生斜坡**,
  天生就走得上去,`openPlateaus()` 在本鎮只是保險。
- **原生游泳池是 2×2、佔 (16–17,15–16)**(2026-07 實機確認,`sim/presets/lake.json` 與
  `sim/index.html` 的內嵌字串都已補成 4 格)。初版抄錄只記了 (16,15) 一格,體育館因此排在
  (17–18,16–17)、**與真實泳池重疊 (17,16) 一格**;而 `verify.js` 的「拆除的既有建築」是
  **同型別仍存在就不敏感**,抓不到這種「蓋在既有建築上」的重疊 —— 改地形資料時要自己回頭
  對一次多格既有建築的每一格。現在體育館挪到 **(17–18,17–18)**(該街廓唯一不壓泳池、
  又四面貼得到路的 2×2),足球場 (18,15)、社團教室② (18,16),熱血窗口從 W(15,14) 變 W(15,15)。
- **`landscapeDeadPockets()`(草地版)**:`tidyUnreachable()` 只處理鋪面,本鎮收尾再把
  走不到的**草地**口袋(9 格)種成樹林(逐格守衛,景點變少就退回),
  結果「走不到的通行格 = 0」,是五鎮唯一做到的。
