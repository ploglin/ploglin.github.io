## 多尺寸支援

- `gridRows`/`gridCols` 為變數,`setGridSize(rows, cols, preserve)` 重建網格;工具列「地圖尺寸」下拉**五鎮各自一個選項**(依城鎮順序:健康/東部/湖畔/溪谷/百靈;value 帶 `-城鎮` 後綴以區分同尺寸城鎮)。
- `PRESETS` 每鎮帶 `rows`/`cols`;`data: null` 的城鎮選取後以正確尺寸開空白畫布。
- 分享碼:非 26×24 時帶 `RxC;` 前綴;**26×24 維持無前綴,舊連結與外部產生器完全相容**。`decodeMap` 依前綴解碼,`importGridData` 依陣列尺寸自動切換畫布。
- 座標軸:X = r+2、Y = gridCols+1−c(各鎮皆從 [2,2] 起算,與實機一致)。
- `scripts/check.js` 驗證各內建圖尺寸(MAP_SIZES)、26×26 前綴格式往返與「26×24 無前綴」守護檢查。

## east.json

使用者實機手繪抄錄的冬郵小鎮開局地形(2026-07 定稿),26×26,座標 [2,2]–[27,27]。
(手繪時畫布多出的最左欄與最底列已於收錄時裁掉。)
與 `sim/index.html` 的 `PRESET_EAST_DATA` 內容一致(單行字串、無 bid,
匯入時由 `assignBlockIds()` 自動補回多格建築的 bid);改地形時兩處要同步,
並跑 `node scripts/check.js`。

## lake.json / valley.json / hill.json

使用者實機手繪抄錄的湖岸小鎮(24×24)、溪谷小鎮(26×26)、百靈山丘(26×26)開局地形
(2026-07 入庫),格式與 east.json 相同:單行字串、無 bid,與 `sim/index.html` 的
`PRESET_LAKE_DATA` / `PRESET_VALLEY_DATA` / `PRESET_HILL_DATA` 內容一致,改地形時兩處要同步。

照實保留的資料特性(不是要修的 bug):

- **湖岸圖有 1 格 `pool`**(游泳池現已登記 2×2)——使用者在舊版模擬器畫的,
  朝向待實機確認;`assignBlockIds()` 對湊不齊 w×h 的格子只是不給 bid,不會報錯。
- **百靈圖**有一座 2×2 `gym`、兩座 1×2 `tennis`、一座 1×2 `basketball`,均照原樣收錄。

**改冬郵地形後,完美佈局也要重跑**:`scripts/layout-gen/` 底下
`node east.js && node gen-assets.js east`,再把新的分享碼與表格貼回
`layouts/east/index.html`,最後 `node verify.js east page` 必須全 PASS。

已知的地形性質(由 `layout-gen/verify.js` 與泛洪檢查得出,不是 bug):

- **田埂路(`aze_path`)在模擬器裡不可通行**,所以原始地形有幾棟建築(網球場、百葉箱、
  小農場)一開始就被判成「走不到」——那是地形本身造成的,不是資料錯誤。
- **高地上鋪的是草地/竹林而非空地時不會生成斜坡**,整片高地一開始沒有任何坡道。
- **東南角有一塊 39 格的陸地被水塘圍住**(座標約 X13–X27 / Y2–Y7),初始狀態下
  跟地圖其餘部分沒有任何相連格,島上有兩間既有養豬小屋(X13/Y2、X14/Y2)。
  但**水塘可以被建設覆蓋、破壞成平地**(實機確認),所以那不是死地——
  完美佈局在 X21/Y5、X21/Y4 破壞兩格水塘就把它接上動線,養豬小屋原地保留。
